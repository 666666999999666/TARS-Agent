# 工程验证与 Agent 评测

本目录公开运行时改动、验证范围、AppWorld 对照方法和脱敏结果。原始轨迹、应用数据、请求与费用账本、凭证及本机路径不随仓库发布。

| 文档 | 内容 |
| --- | --- |
| [工程验证](VALIDATION.md) | 当前公开候选与历史实测的区别，失败、修复和仍未验证的范围 |
| [实验方法](EXPERIMENT.md) | 唯一提示差异、任务选择、隔离、预算、恢复及选版条件 |
| [结果与限制](RESULTS.md) | AppWorld train/dev 分数、成本、负面案例及内部单／多 Agent 对比 |
| [复现说明](REPRODUCE.md) | 零模型请求的公开摘要复核，以及使用自己环境重跑的步骤 |
| [结构化摘要](results.json) | 脱敏逐题结果、来源摘要、汇总和人工副作用统计 |

历史 AppWorld 完整 dev 单轮 A/B 对照中，A 通过 20/57 题、B 通过 54/57 题。B 只改变完成协议提示，主要减少把完成总结当作答案提交的错误；没有提速结论，仍存在意外修改和输出上限失败。旧 `test_normal` 的 63/168 题是未完成实验，不与 dev 成绩合并。

结构化摘要可使用标准库脚本离线复算：

```powershell
python scripts/verify_eval_summary.py
```

命令需在仓库根目录运行，不启动模型、Docker 或账本，也不写回结果。它验证公开记录的完整性并复算指标，**不等于从最终应用状态重新运行官方 evaluator**；原始状态与评分轨迹未公开。AppWorld 官方代码和数据按其自身许可及获取方式使用。

普通 CLI/TUI 使用见[运行手册](../../RUNBOOK.md)。公开候选的工程测试与历史模型实验分开记录，不能把一次代码发布写成又做了一轮模型评测。
