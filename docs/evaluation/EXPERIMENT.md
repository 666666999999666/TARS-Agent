# AppWorld：完成协议提示的单轮对照

本实验研究一个具体问题：模型完成了应用修改，却把完成总结放入 `complete_task(answer=...)`，导致官方答案检查失败。历史 train `692c77d_1` 的状态修改和副作用检查通过，答案检查失败，因此在 train 提出假设后，只改变任务结束说明。

## 唯一实验变量

- A 保留原完成说明。
- B 说明执行类任务省略 `answer`；明确要求答案的任务按要求提供答案；完成总结不写入 `answer`。

两段模板见 [appworld_prompts.py](../../src/tars_agent/core/eval/appworld_prompts.py)。模型仍负责理解目标、查阅 API 和生成代码。适配器只转发 `appworld_execute(code)`，不推断题型、不改写代码、不读取标准答案。B 不增加反思轮次、子 Agent、工具或调用预算。这项改动称为“完成协议提示改进”。

## 固定条件

| 项目 | 冻结值 |
| --- | --- |
| 被测源码 | 本地实验提交 `a7b0f68a7aefd33b47eb93701bbdbd51a0a70378`；它是历史来源标识，不是公开仓库的可检出版本 |
| 模型与协议 | 官方 `deepseek-flash`，`https://api.deepseek.com/anthropic`，Anthropic Messages；核对完整响应的实际模型，不自动切换 |
| 思考配置 | 不发送额外思考参数，沿用服务默认；不等于关闭思考 |
| AppWorld | 官方提交 `42b5bcf3cd334fee33f0c37c02070a9f5807add5`，数据 0.2.0 |
| 环境 | 独立 Linux Docker 镜像，SQLModel 固定 0.0.44；官方源码、任务及评分器未改 |
| 单次预算 | 60 个模型步骤、900 秒、8192 最大输出 Token、131072 本地上下文预算；每步最多两次 HTTP 尝试 |
| 调度 | 单 worker；固定排序，A/B 交错且交替谁先执行；每次新会话、新世界 |
| 重跑 | 普通失败不重跑；无法评分的基础设施失败最多补跑一次，原始尝试保留 |

131072 是本地输入预算政策，按 UTF-8 JSON 字节等信息保守估计，不代表精确 tokenizer 计数或已核实的服务端窗口。接口由服务商维护，固定客户端配置不能保证将来得到相同响应。

train 固定四个场景 `692c77d`、`22cc237`、`27e1026`、`76f2c72` 的各三个变体，共 12 题；A/B 各一次，24 次运行。冻结后执行完整 dev 57 题、19 个场景，A/B 各一次，114 次运行。公开清单为 [train](../../evals/appworld-deepseek-train-paired.json) 和 [dev](../../evals/appworld-deepseek-dev-paired.json)。train 是诊断子集，不代表全部 train。

本轮不运行完整 `test_normal`；旧 63/168 不用于调提示，也不拼接成绩。dev 开始后没有换题、按局部分数改提示或择优保留样本。完成批次共 138 次运行均可评分，没有基础设施补跑；模型运行失败也保存状态并进入官方评分。

## 状态隔离、保存与恢复

[评测驱动](../../src/tars_agent/core/eval/appworld.py)管理世界初始化、保存、关闭及官方评分；[worker](../../src/tars_agent/core/eval/appworld_worker.py)通过 RuntimeService 运行被测 Agent。管理能力、标准答案和评分文件不作为 Agent 工具提供。结束时等待在途执行停止，再保存最终状态；无法确认资源身份、服务停止或状态保存时暂停批次。

批次记录源码树、Python 环境、模型配置、提示哈希、数据和镜像身份。恢复必须匹配原记录，不覆盖已经完成的结果，不刷新重跑次数或额度。仓库中的文档也参与树摘要，因此仅修改文档同样可能使旧批次拒绝恢复。

AppWorld 管理端口只发布到宿主 loopback，使用独立 Docker bridge；容器出站网络未被禁用。它与本地文件工具的 `network=none` 沙箱是不同边界。Linux 上 AppWorld 调度器崩溃后真实进程退出确认仍缺专项实测，不据此宣称跨平台恢复已全面验收。

## 费用与中断

原累计请求账本持续计数，另以一次初始化的 50 元费用账本控制新增支出。每次 HTTP 发送前按冻结高峰价保守预留，完整且有效的模型用量返回后结算；取消、超时或用量未知的预留不按零处理。下一请求可能超过剩余额度时停止发送并保存检查点。

第一批 `001` 在费用校验文件发布故障后停止。核对并保全账本后，公共实现增加有限 I/O 重试，再以新批次 `002` 完整执行。旧结果、原金额和未知预留均保留，`001` 不参加 `002` 分数计算。此工程修复发生在完整对照前，A/B 使用相同修复后的实现。细节见[工程验证](VALIDATION.md)。

## 评分与选版条件

TGC 是官方全部检查通过的任务比例；SGC 是三个变体全部通过的场景比例。官方成绩与 TARS Run 状态、请求量、耗时和可确认 Token 分列。

预先约定采用 B 的条件是工程验收通过、dev TGC 高于 A，且官方意外修改相关失败检查数量不增加。自动分类不能可靠区分“缺少目标修改”和“额外修改”，因此保持自动值为未知，另从官方失败 trace 人工复核。人工统计不是 AppWorld 官方安全总分，不能替代逐题负面案例。

历史候选满足上述条件，选定 [B 单版清单](../../evals/appworld-deepseek-selected.json)；它显式设置 `paired_comparison=false`、`prompt_variant=B`。源码默认 A、普通任务默认行为和 A/B 清单不变，新增单版清单未再付费运行。完整数字、B 新增副作用及选择限制见[结果](RESULTS.md)。这是单轮配对观察，没有稳定提升、统计显著性或通用规划能力提升的结论。
