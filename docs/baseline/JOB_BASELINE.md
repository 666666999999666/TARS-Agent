## 从哪里开始学习和使用

先读 [README](../../README.md) 的首次准备与 CLI 入口、[RUNBOOK](../../RUNBOOK.md) 的受信配置与累计额度，再沿 [ARCHITECTURE](ARCHITECTURE.md) 阅读 Session/Turn/Run、审批/执行和事件收尾三条链。现阶段暂停付费验收，阅读、离线测试和讲解不需要启动模型。

以后另行决定运行模型时，使用新的合成工作区，放入 `docs/w05/input.csv` 或 `input-alternate.csv`，并把 `docs/w04/demo.md` 复制为工作区 `.tars/skills/demo.md`。保持原累计账本，确认受信配置中的模型/预算和 Docker required；不照搬本机历史目录、账本数字或旧请求上限。

已有离线预检查与独立核验入口：

```text
uv run --no-sync python scripts/check_demo_preset.py --workspace <演示工作区> --evidence <工作区外的证据目录>
uv run --no-sync python scripts/verify_csv_report.py --input <input.csv> --report <report.json> --sha-file <任务开始前保存的输入哈希文件>
```

预设缺失或工具范围不符就停止。初始哈希必须在任务前保存，不能为了让核验通过而重建；现有未知 Skill 回退未修。真正提交和审批使用正式 `tars chat` 或 `tars run --goal`，由本人完成；不要把自动脚本代提交、代批准当成本人操作证据。

当前项目介绍应按本人能够解释的范围表述。三项技术自测、独立小修改和故障定位能力仍需本人完成，不能由这份基准或既有代码自动推定个人贡献。
