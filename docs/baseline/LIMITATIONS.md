# V1 已知限制与验证边界

本页记录 TARS-Agent V1 的实际使用边界。版本与验证结果见[V1 基准记录](VERIFICATION_SUMMARY.md)。

## 已验证环境的边界

- 本次在 Windows、项目自己的 Python 3.12 环境及 Docker Desktop Linux 引擎上执行。真实 TUI 是 Textual/Windows ConPTY 进程，通过项目现有 xterm.js 桥接收键盘并显示画面；检查了实际 Textual 深浅主题与小窗口。原生 Windows Terminal 的特定字体和中文输入法未独立验收。
- Web 浏览器检查覆盖认证、只读限制及游标恢复。面板固定使用深色配色，系统浅色和深色模式下均检查了实际截图。Node/npm、Chromium 和终端桥仅属于构建或验收工具，日常 TUI 不依赖它们。
- 普通进程可能没有创建符号链接的权限；符号链接安全用例需要单独区分通过和权限跳过，junction 测试不能替代它。日常普通文件任务不要求管理员身份。

## 模型与工具结果

- 真实验收中出现过 `llm_protocol_error`，也出现过 `llm_total_timeout`。程序将对应 Run 明确记为失败，恢复输入；之后的新请求能够继续。现存记录不足以判定服务端响应与 SDK 解析的具体原因，不能声称此类外部请求永不失败。
- 模型在三角色任务中曾算错标记字符数。实际文件通过独立读取核对；模型的解释仍需检查，子 Agent 的存在不保证判断一定正确，也没有测量其相对单 Agent 的收益。
- 工具记录为 `cancelled` 或 `interrupted` 表示没有取得正常最终返回，不证明副作用已回滚。Run 的取消完成须经过资源清理确认；外部 MCP 服务已接受的操作不保证能撤销。
- TUI 审批显示参数摘要，长命令和子任务提示可能被截短；完整参数保存在运行记录中。CLI 审批打印完整 JSON 参数；TUI 仍没有独立的完整参数展开界面。
- 本地 MCP 验收覆盖受控 stdio/HTTP 服务和故障处理，不等于所有外部账号、服务或工具均已验证。MCP 不提供自动重连扩展；本地启动归属与关闭 token 也不等于全部 IPC 请求已有完整认证。

## 数据与使用方式

- 不自动读取或迁移其他目录中的个人会话、数据库、日志和授权；数据根由受信配置指定。
- SQLite 是 Session、Run、消息和持久事件的依据。笔记、模型计划项和 JSONL 仍各自保存为文件；计划项只属于当前 Run，不是跨会话待办系统。
- 正式入口是 `tars chat [--resume <session_id>]`、`tars run --goal "任务"` 和 TUI。两个 CLI 任务入口共用 `cli/client.py`，不另建 AgentLoop；客户端退出不调用 `session.close` 或 `core.shutdown`。
- V1 的 CLI 每次 Enter 提交一行，不把多行粘贴合并为一个任务。Windows ConPTY 的额外探针复现过多行粘贴后记录缺少结果尾部与下一提示，但后续任务仍能提交并正常退出；具体显示原因未确认。真实验收通过的是单行聊天流程，不据此宣称多行粘贴显示已解决。
- chat 运行中 Ctrl+C 取消当前轮后继续交互，空闲 Ctrl+C 退出 `130`，EOF 退出 `0`。goal 正常为 `0`、失败为 `1`、参数错误为 `2`、取消为 `130`；任一已发生的工具失败，即使随后补救成功也返回 `1`。
- goal 在主 Run 结束时退出，列出尚未结束的后台子 Run，但不等待它们；客户端退出以后发生的子任务结果应单独查询。非交互 CLI 需要审批时拒绝操作，不能依靠管道中的回答自动授权。
- `llm.router`、`sandbox.enabled` 已移除，旧配置保留这些字段会明确报错。
- reviewer 仅有读取和列目录工具，不能执行 shell 或测试命令。`/orchestrate` 已补齐父级文件工具白名单，子角色仍受父权限交集与审批约束。
- 长会话恢复可能出现有提示的事件流溢出，然后从已确认游标继续回放。恢复期间要等输入框重新可用；本次没有自动重新执行历史任务。

## 计量与后续范围

请求账本按发送前保守预占累计；失败、重试、压缩和子 Agent 共同计数，不清零或自动退回不确定请求。测试状态与用户会话库隔离，模型配置和请求账本仍使用原路径。一次验收授权不代表后续任务自动获得同样额度。

`run.metrics` 不是账户账单。手动压缩的部分使用量没有进入 Run 事件投影，完整账户 token 和费用未确认，不据此编造成本或性能收益。

AppWorld、OTLP 等实验扩展未进入本次 V1。后续优先从已遇到的问题中选一个：完整审批参数查看、模型协议错误的脱敏诊断、长历史回放体验；本次不提前建设新的框架。

CLI、TUI、RPC 和安装包分别记录验收；覆盖率必须对应实际源码，不能只靠 `--help` 或旧报告宣布新版本通过。
